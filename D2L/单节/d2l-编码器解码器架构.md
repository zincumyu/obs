# D2L《编码器-解码器架构》大白话笔记

> 原文链接：https://zh.d2l.ai/chapter_recurrent-modern/encoder-decoder.html

## 这节在解决什么问题

机器翻译：输入一句英文，输出一句中文。比如：

```
输入: "They are watching."   （3 个单词）
输出: "他们正在看。"           （5 个字）
```

问题来了：**输入和输出的长度不一样，而且谁都不知道会多长**。而之前学的前馈网络、CNN，全都是"输入多大、输出多大"定死的框框。所以需要一个新的通用架构，这就是编码器-解码器。

## 核心就两个零件

可以把它想象成一个**翻译员的工作流程**：

1. **编码器（encoder）**：把可变长度的输入序列"读进去"，压缩成一个**固定形状的"编码状态"**（书里叫 encoded state，也叫上下文向量）。
   - 类比：翻译员先**完整听完**整句英文，在脑子里形成一个"这句话啥意思"的概括。

2. **解码器（decoder）**：拿这个固定形状的状态当原料，一步步"吐"出可变长度的输出序列。
   - 类比：翻译员再根据脑子里的那个意思，**用中文一个字一个字说出来**。

流程图：

```
输入序列 ──▶ [编码器] ──▶ 状态（固定形状的向量）──▶ [解码器] ──▶ 输出序列
(变长)                        (中间表示)                 (变长)
```

> **一句话总结**：编码器负责"读懂并压缩"，解码器负责"根据压缩件重新展开"。中间那个固定形状的向量，是两端唯一的"接头"。

## 为什么正好用 RNN 来当这两个零件

上一章刚学过循环神经网络，这里直接对上号了：

- RNN 天然能处理变长输入 → 很适合当编码器：把整句话读完，**最后一个隐藏状态**就是那个"编码状态"。
- RNN 也天然能一步步生成 → 很适合当解码器：以上面那个状态为起点，一个词一个词地往外蹦。

所以"编码器-解码器"并不是某个具体的网络，而是一个**通用的套路**；RNN 是当时最顺手的实现方式（后面讲注意力机制、Transformer 时还会继续改进它）。

## 记住两个术语

- **seq2seq（序列到序列）**：输入是序列、输出也是序列、且两边长度不定的任务，比如机器翻译。编码器-解码器就是它的标准解法和别名，所以很多地方两个词混着用。

## 看完这节你该有的感觉

就是："哦，翻译 = 先读进去压成一个意思，再按这个意思重新说出来。" 具体编码器怎么压、解码器怎么吐、训练时哪里来的"标准答案"、预测时怎么挑词——那些都在**下一节 seq2seq** 里展开，配合代码看会顺畅很多。
